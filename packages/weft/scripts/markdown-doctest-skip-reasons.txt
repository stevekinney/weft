# Allowed reasons for skipping a TypeScript code block in documentation/.
# Each reason represents a valid intent for a non-runnable snippet.
#
# Used by scripts/extract-markdown-doctests.ts. Adding a reason here is a
# conscious decision — every entry should describe a category that genuinely
# can't be expressed as a standalone, type-checkable example.
#
# Fence usage:
#   ```ts <reason>
#   ```ts no-check:<reason>
# Both forms are accepted.

# Snippets that show only a fragment of a function or expression — useful
# for highlighting one piece of an API without the full setup boilerplate.
partial

# Pseudocode for explaining an idea, where the prose is teaching the concept
# rather than the literal API call.
pseudocode

# Verbatim output the user would see (error messages, log lines, JSON
# transcripts that are not source code, command output that happens to be
# tagged ts because of a syntax-highlighting quirk).
output

# Examples that intentionally show invalid or broken code to illustrate a
# pitfall. Type-checking these would defeat the point.
counter-example

# Examples that depend on declaration merging or external types not on the
# public surface (e.g. extending the global Window interface for a browser
# adapter); typechecking against the source-side `paths` map would fail
# with no productive fix.
declaration-merging
