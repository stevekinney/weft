# PR 25 — Engine coordination operation extraction

## Scope

Extracts coordination operation handling from `src/core/engine/index.ts` into
`src/core/engine/operations-coordination.ts`.

This PR follows the existing engine split pattern: extracted helpers run as
module-level functions that receive `EngineInternals` first, with a callbacks
bundle for private `Engine` capabilities that remain on the class.

## Files added/changed

- `src/core/engine/operations-coordination.ts` — signal waiting, parallel,
  race, run-all operation processing, and run-all branch execution helpers.
- `src/core/engine/index.ts` — imports the extracted helpers, routes
  coordination operations through `operations-coordination.ts`, and removes the
  extracted private `Engine` methods.
- `documentation/engine-split-log/PR-25.md` — records this extraction.

## Functions extracted

Private `Engine` methods moved to module-level functions:

- `#processWaitSignalOperation`
- `#processParallelOperation`
- `#processRaceOperation`
- `#processRunAllOperation`
- `#executeRunAllOperationResult`
- `#isConfiguredInlineActivity`

## Notes

- `#executeSubOperation` remains on `Engine` because it is still called by the
  speculative generator driver outside the extracted coordination-operation
  routing path.
- `operations-coordination.ts` imports `EngineInternals` from `./internals.ts`
  and does not import from `src/core/engine/index.ts`.
- `CoordinationOperationCallbacks` carries the remaining instance-private
  capabilities needed by the extracted functions, including operation
  completion, result wrapping, sub-operation execution, and activity operation
  callback creation.
- Replay determinism is preserved by keeping the original await ordering and
  the existing `Promise.all`, `Promise.race`, and `Promise.allSettled` usage.
- Dead private `Engine` shims are deleted rather than retained through
  `void this.#method` references.
