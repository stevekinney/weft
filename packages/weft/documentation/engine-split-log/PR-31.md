# PR 31 - Engine termination extraction

## Scope

Extracts workflow termination methods from `src/core/engine/index.ts` into
`src/core/engine/termination.ts`.

This continues the `EngineInternals` sibling-module pattern: termination
functions take `EngineInternals` first, receive typed parameters, and call back
into engine-only behavior through `TerminationCallbacks`.

## Files added/changed

- `src/core/engine/termination.ts` - new termination sibling module containing
  cancel, timeout, terminal cleanup, workflow completion, workflow failure, and
  pending-timeline finalization helpers.
- `src/core/engine/index.ts` - termination entrypoints and internal call sites
  now delegate into `termination.ts`.
- `documentation/oxlint-disable-inventory.md` - tracks the temporary
  `core-engine-termination-file-length` disable.
- `documentation/engine-split-log/PR-31.md` - this split log.

## Replay-determinism rules respected

- `completeWorkflow` keeps the original state write, deadline cancellation,
  memory cleanup, event dispatch, broadcast, resolver settlement, and scheduled
  handoff order.
- `failWorkflow` keeps the original attribute read, state update, attribute
  cleanup, deadline cancellation, retained-attribute write, terminal cleanup,
  event dispatch, resolver rejection, and scheduled handoff order.
- `terminateWorkflow` keeps the original terminalizing marker, strategy
  cancellation, attribute read, state update, retained-attribute write, timer
  cancellation, durable cleanup, event dispatch, resolver rejection, and marker
  removal order.
- No await boundaries were merged or reordered.
- Event emission positions relative to storage writes are unchanged.

## Implementation notes

`TerminationCallbacks` carries all engine-only behavior needed by the extracted
functions. Timeline helpers moved as direct module-level functions because they
only read and write `EngineInternals`.

`#cleanupWaiters` now cancels review timers through
`callbacks.swallowPromiseRejection`, matching the extraction rule that
cross-method behavior goes through typed callbacks rather than private-method
workarounds.

## Dependent PRs

`core-engine-file-length` disable remains until the main engine file drops below
the configured threshold.
