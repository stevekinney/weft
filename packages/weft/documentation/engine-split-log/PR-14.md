# PR 14 — Engine listing and attributes/tags extraction

## Scope

Extracts workflow listing, search-attribute access, tag mutation, and
attribute/tag index helpers from `src/core/engine/index.ts` into
`src/core/engine/listing.ts` and `src/core/engine/attributes-tags.ts`.

This PR keeps the `Engine` public method surface intact. Public listing and
attribute/tag methods now delegate to module-level functions that receive
`EngineInternals` as their first argument. Private listing and attributes/tags
helpers were removed from the `Engine` class.

## Files added/changed

- `src/core/engine/listing.ts` — workflow listing, workflow-state streaming,
  search-attribute access, and single-workflow public tag helpers.
- `src/core/engine/attributes-tags.ts` — attribute/tag index queries,
  constrained-ID resolution, attribute cleanup, terminal attribute retention,
  workflow-state updates, and tag mutation helpers.
- `src/core/engine/storage-io.ts` — exports
  `runSerializedWorkflowStateWrite()` so extracted state mutations can preserve
  the existing serialized write boundary.
- `src/core/engine/index.ts` — imports the extracted helpers and retains thin
  public shim methods in the `Engine` class.
- `documentation/oxlint-disable-inventory.md` — moves the extracted oxlint
  disable inventory entries to their new files.

## Notes

- `listing.ts` imports `resolveConstrainedIds()` and tag helpers from
  `attributes-tags.ts`.
- `attributes-tags.ts` does not import from `listing.ts`; bulk tag mutation
  snapshots matching workflow IDs locally to preserve the requested one-way
  dependency.
- The constrained-ID fast path in `list()` preserves the existing
  `Promise.all()` fan-out and deterministic ordered iteration.
- Serialized workflow-state writes still use the same per-workflow write chain
  through the exported `runSerializedWorkflowStateWrite()` helper.
- No public exports were added from `src/core/engine/index.ts`.
