# PR 16 — Engine retention extraction

## Scope

Extracts retention configuration checks, retention sweep scheduling, sweep
execution, and retention overview helpers from `src/core/engine/index.ts` into
`src/core/engine/retention.ts`.

This PR keeps the `Engine` public method surface intact. The public retention
overview method and private retention helpers now delegate to module-level
functions that receive `EngineInternals` as their first argument.

## Files added/changed

- `src/core/engine/retention.ts` — retention configuration detection, sweep
  timer scheduling, sweep execution, per-workflow-type retention resolution,
  and retention overview assembly.
- `src/core/engine/index.ts` — imports the extracted helpers and retains thin
  shim methods in the `Engine` class.
- `documentation/engine-split-log/PR-16.md` — records this extraction.

## Functions extracted

Public `Engine` methods moved to module-level functions:

- `getRetentionOverview`

Private `Engine` methods moved to module-level functions:

- `hasConfiguredRetention`
- `setNextRetentionSweepAt`
- `ensureRetentionSweepInterval`
- `runRetentionSweep`
- `resolveWorkflowTypeRetention`

## Notes

- `ensureRetentionSweepInterval()` preserves the existing `setInterval`
  behavior, including updating `nextRetentionSweepAt` before every attempted
  sweep and skipping new work while a previous sweep remains in flight.
- `runRetentionSweep()` receives cleanup error reporting and waiter cleanup
  callbacks from `Engine`, keeping private Engine behavior centralized while
  moving the purge orchestration out of the class.
- Retention purge scanning and purge storage cleanup remain in
  `src/core/engine/bulk-operations.ts`; this extraction imports
  `purgeInternal()` rather than moving those helpers again.
- No oxlint disable inventory entries moved because the extracted retention
  methods did not contain oxlint disable directives.
