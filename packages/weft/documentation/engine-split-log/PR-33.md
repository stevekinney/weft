# PR 33 - Aggressive Engine class-split attempt (proven infeasible)

**Date:** 2026-05-25
**Task:** `3765ffa6-1430-4be5-970c-c0f984ff34df` — "Break apart `src/core/engine/index.ts`
under the 500-line max-lines ceiling (aggressive class split)."

## Scope

This task took the **aggressive** path that the prior split (`161ddf64`, logged through
PR-32b) explicitly declined: drive `src/core/engine/index.ts` under the oxlint `max-lines`
ceiling (`{ max: 500, skipBlankLines: false, skipComments: false }`) and **remove** the
file-level `/* oxlint-disable max-lines */` suppression — which necessarily means splitting
the public `Engine<TWorkflows, TActivities>` class declaration itself, not just relocating
free functions or method bodies.

The attempt was run behind a pre-committed decision gate protecting the published type
surface (a parser-extracted, byte-identical `Engine` class-block `.d.ts` oracle plus
whole-export-chain topology diffs and call-site inference type tests). The conclusion is
**proven-infeasible**: the aggressive sub-500-with-suppression-removed outcome cannot be
reached without regressing the public `.d.ts`. This record captures the evidence.

## Measured line counts

- `src/core/engine/index.ts` at start: **1,396** lines.
- **Irreducible class declaration floor: ≥ 531 lines.** Counting the footprint that survives
  even if every method body is reduced to nothing (using oxlint's own rule —
  `skipBlankLines: false, skipComments: false`):
  - overload signatures ~191: `static create` ×4 = 29; `register` ×3 = 20; the five bulk
    methods' dry-run+commit+impl sigs ~75; `signal`/`update`/`query` ~40; `schedule` ~17;
    `start` ~10;
  - public-member JSDoc ~130;
  - ~50 single-method signature lines;
  - class scaffolding ~10;
  - the type-only imports those signatures require ~150.

  This floor exceeds 500 **before a single delegating body line is counted**, so no amount of
  body extraction can reach the ceiling.

- Surface-preserving extractions actually landed (relocate
  `assertCompatiblePersistedDataVersion` + `EngineStateNamespace`, extract the
  `[Symbol.dispose]` body): **1,252 lines** — a real 144-line reduction, still far above 500.
  The constructor-body extraction was evaluated and **deliberately declined**: its natural
  home (`construction.ts`) intentionally avoids importing `Engine` to break an import cycle,
  but the body's `new WeakRef(this)` feeds `Engine`-typed runtime helpers, so extraction would
  force either a cycle-violating `Engine` import or an `as` cast (against repo policy), or a
  new sibling whose only purpose is to host straight-line initialization glue. With the sub-500
  goal already unreachable, that indirection buys nothing — so the ~120-line constructor stays
  inline.

Because the irreducible declaration floor alone is ≥ 531, the **only** path under 500 is to
physically split the `Engine` class declaration across modules. Both available mechanisms fail
the gate.

## Techniques attempted

### 1. Verbatim class move to a sibling + re-export (ruled out by repo-wide `max-lines`)

Moving the ~1,035-line class body verbatim to a new `src/core/engine/engine-class.ts` and
re-exporting it from `index.ts` would shrink `index.ts`, but `max-lines: 500` applies
repository-wide to production `src/**/*.ts` (the only `.oxlintrc.json` `off` overrides are
`**/*.svelte`, `scripts/**`, and test files). The receiving file would itself violate
`max-lines` and require its **own** suppression. This relocates the suppression; it does not
remove it. The task's goal is removal, so this is not success. (No spike needed — arithmetic.)

### 2. Class-expression mixin (`WithSchedules(EventTarget)`) — spiked, regresses the `.d.ts`

The one bounded feasibility probe: convert the schedules method family (the safest spike —
no generics widening the class's own type parameters, no static members) into a
class-expression mixin and have `Engine extends WithSchedules(EventTarget)`. Built it,
emitted declarations, and diffed the scoped `Engine` class block against the Phase-0 baseline.

**The public-surface gate FAILED.** Exact diff (`tmp/engine-class-baseline.d.ts` `<` vs.
mixin probe `>`):

```diff
< export declare class Engine<...> extends EventTarget implements Disposable, AsyncDisposable {
---
> export declare class Engine<...> extends Engine_base implements Disposable, AsyncDisposable {
169,176d168
<     schedule<TInput>(definition: ScheduleDefinition<TInput>, accessOptions?: ScheduleAccessOptions): Promise<ScheduleHandle>;
<     schedule(type: string, input: unknown, cronExpression: string, options?: ScheduleOptions, accessOptions?: ScheduleAccessOptions): Promise<ScheduleHandle>;
<     getSchedule(scheduleId: string, accessOptions?: ScheduleAccessOptions): Promise<ScheduleSummary | null>;
<     listSchedules(filter?: ScheduleFilter): Promise<PaginatedResult<ScheduleSummary>>;
<     pauseSchedule(scheduleId: string, accessOptions?: ScheduleAccessOptions): Promise<void>;
<     resumeSchedule(scheduleId: string, accessOptions?: ScheduleAccessOptions): Promise<void>;
<     cancelSchedule(scheduleId: string, accessOptions?: ScheduleAccessOptions): Promise<void>;
<     updateSchedule(scheduleId: string, newCronExpression: string, accessOptions?: ScheduleAccessOptions): Promise<void>;
```

Two distinct public-surface regressions:

1. The flat, self-documenting `extends EventTarget` became `extends Engine_base`, where
   `Engine_base` is a synthetic, `any`-typed composed-constructor intersection TypeScript
   emits for the mixin:

   ```ts output
   declare const Engine_base: {
       new (...args: any[]): {
           schedule<TInput>(...): Promise<ScheduleHandle>;
           /* ...the other schedule methods... */
       };
   } & {
       new (): EventTarget;
       prototype: EventTarget;
   };
   ```

   This is the "composed-constructor intersection instead of a flat `class Engine<TW,TA>`"
   that the prior task and three independent Codex consultations predicted. It also contains
   `new (...args: any[])`, which violates the repo's `any` ban in production declarations.

2. All eight schedule method signatures **left the `Engine` class declaration** and now live
   on `Engine_base`. A consumer or docs generator reading `Engine`'s `.d.ts` no longer sees
   them as `Engine` members — the published surface is split across two declarations.

### 3. `declare class Engine` hand-written facade (ruled out by arithmetic)

A hand-authored `declare class Engine` would restore a flat `.d.ts`, but then all ~191
overload-signature lines plus ~130 member-JSDoc lines must live in a counted production file
(`index.ts` or a `.d.ts` that oxlint still counts), so it cannot beat 500 either. No spike
needed.

Mixins over the generic-bearing methods (`register`'s `TWorkflows` widening return type) and
the instance-invisible `static create` overloads are strictly worse than the schedules spike
and are ruled out a fortiori.

## Decision

The aggressive outcome (sub-500 with the suppression removed) is **proven infeasible** under
the hard constraint that the emitted `Engine` class-block `.d.ts` stay byte-identical. Every
class-splitting technique either regresses the published declaration (mixins / the composed
`Engine_base` intersection) or merely relocates the `max-lines` suppression to another
production file (verbatim move), or cannot beat the arithmetic floor (`declare class` facade).

The reachable, surface-preserving outcome is the Phase-0 type-only regression oracles
(landed in this branch as durable coverage) plus a **sharpened residual suppression** on
`index.ts` recording this attempt. This required task-owner sign-off. The two acceptable
terminal states were: (a) suppression removed — not reachable — or (b) decision recorded with
explicit owner authorization of the residual. The owner chose (b) on 2026-05-25 and authorized
the surface-preserving extractions below.
