# PR 18 — Engine query extraction

## Scope

Extracts workflow query resolution from `src/core/engine/index.ts` into
`src/core/engine/queries.ts`.

This PR keeps the `Engine` public method surface intact. The public `query`
method now delegates to a module-level function that receives
`EngineInternals` as its first argument.

## Files added/changed

- `src/core/engine/queries.ts` — built-in activity progress query resolution
  and inline workflow exposed accessor lookup.
- `src/core/engine/index.ts` — imports the extracted helper and keeps a thin
  `Engine` shim.
- `documentation/engine-split-log/PR-18.md` — records this extraction.

## Functions extracted

Public `Engine` methods moved to module-level functions:

- `query`

Private `Engine` methods moved to module-level functions:

- None.

## Notes

- `query()` preserves the built-in `activityProgress` query path before
  checking inline execution support.
- `query()` uses a narrowed `inlineStrategy` local after the worker-strategy
  guard, so the extracted helper does not need a non-null assertion or oxlint
  disable directive.
- `queries.ts` does not import types or values from `index.ts`; it imports only
  `EngineInternals` from `./internals.ts` to avoid introducing an import cycle.
- No oxlint disable inventory entries moved because the extracted query method
  did not contain oxlint disable directives.
