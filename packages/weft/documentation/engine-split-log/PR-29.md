# PR 29: Child Workflow Operation Extraction

## Scope

- Moved child workflow, handoff, debate, and supervise operation handling from `src/core/engine/index.ts` to `src/core/engine/child-workflow.ts`.
- Added `ChildWorkflowOperationCallbacks` so the extracted module can start workflows, load workflow state, retrieve handles, compose workflow interceptors, and use the existing operation-result runner without importing the Engine class.
- Updated embedded child workflow sub-operations in `#executeSubOperation()` to call the extracted nesting-depth and child-execution helpers directly.

## Behavior Preserved

- `ctx.startChild()`, `ctx.pipe()`, `ctx.map()`, and `ctx.reduce()` still enforce maximum nesting depth before starting a child workflow.
- Child workflow execution still propagates parent headers, preserves child workflow interceptor behavior, and reuses an existing child handle only when workflow type, input, and tenant match.
- `ctx.handoff()`, `ctx.debate()`, and `ctx.supervise()` still run through the operation-result wrapper and preserve existing AI coordination imports and return values.
- Public API surface is unchanged; no barrel exports were added.
