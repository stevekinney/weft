# PR 19 — Engine update extraction

## Scope

Extracts workflow update handling from `src/core/engine/index.ts` into
`src/core/engine/updates.ts`.

This PR keeps the `Engine` public method surface intact. Public update methods
now delegate to module-level functions that receive `EngineInternals` as their
first argument, with callbacks for instance-only capabilities such as event
dispatch, broadcast delivery, terminal guards, operation completion, and
coordinated update response persistence.

## Files added/changed

- `src/core/engine/updates.ts` — update submission, coordinated update
  delivery, pending update lookup, wait-update processing, and update handler
  invocation.
- `src/core/engine/index.ts` — imports the extracted helpers and keeps thin
  `Engine` shims.
- `documentation/engine-split-log/PR-19.md` — records this extraction.

## Functions extracted

Public `Engine` methods moved to module-level functions:

- `update`
- `getUpdateResult`
- `submitCoordinatedUpdate`

Private `Engine` methods moved to module-level functions:

- `#processWaitUpdateOperation`
- `#dispatchPendingUpdateReceived`
- `#createCoordinatedUpdateResponder`
- `#deliverCoordinatedUpdateToWaiterIfAvailable`
- `#findPendingUpdateByName`
- `#invokeUpdateHandler`

## Notes

- `updates.ts` imports `EngineInternals` from `./internals.ts` and waiter
  tracking helpers from `./signals.ts`; it does not import from
  `src/core/engine/index.ts`.
- The `update()` complexity suppression moved with the extracted implementation
  and keeps the existing `ID:core-engine-update-complexity` identifier.
- Await ordering from the original update paths is preserved, including
  terminal guards before request creation, pending-update checks before waiter
  registration, and coordinated response waits after optional waiter delivery.
- `#invokeUpdateHandler` remains as an `Engine` private shim so
  `#processPendingUpdatesForHandlers` can continue calling it through the
  existing class path.
