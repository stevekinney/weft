# PR 13 — Engine workflow-feed extraction

## Scope

Extracts workflow-feed replay, tail snapshot, subscription, and notification
helpers from `src/core/engine/index.ts` into
`src/core/engine/workflow-feed.ts`.

This PR keeps the `Engine` public method surface intact. Public feed methods
now delegate to module-level functions that receive `EngineInternals` as their
first argument. Private feed helpers were removed from the `Engine` class.

## Files added/changed

- `src/core/engine/workflow-feed.ts` — workflow-feed record types, feed
  constants, replay helpers, subscription management, and post-commit
  notification dispatch.
- `src/core/engine/checkpoint-io.ts` — imports
  `notifyWorkflowFeedCommit()` directly and removes the feed-notification
  callback from `PersistCheckpointCallbacks`.
- `src/core/engine/index.ts` — imports the extracted helpers, re-exports the
  feed types, and retains thin public shim methods in the `Engine` class.

## Functions extracted

Public `Engine` methods moved to module-level functions:

- `replayWorkflowFeed`
- `snapshotWorkflowFeedTail`
- `subscribeWorkflowFeedCommits`

Private `Engine` methods moved to module-level functions:

- `replayWorkflowEventLog`
- `replayWorkflowTokens`
- `notifyWorkflowFeedCommit`

## Notes

- This PR uses Option A for `notifyWorkflowFeedCommit`: the notifier is an
  exported function from `workflow-feed.ts`.
- `checkpoint-io.ts` now imports `notifyWorkflowFeedCommit()` directly instead
  of receiving it through `PersistCheckpointCallbacks`.
- `workflow-feed.ts` does not import from `src/core/engine/index.ts`.
- `workflow-feed.ts` reads token stream chunks through `EngineInternals.storage`
  using the same storage-key scan behavior as `Engine.getStreamChunks()`.
- Replay generator yield boundaries, `for await` loops, and selector branching
  remain structurally unchanged.
- No new public runtime exports were added from `src/core/engine/index.ts`.
