# PR 22 — Engine operation router extraction

## Scope

Extracts operation routing from `src/core/engine/index.ts` into
`src/core/engine/operations-router.ts`.

This PR keeps the `Engine` method surface intact. The engine now delegates the
operation translation, dispatch, completion, failure, and operation execution
wrappers to module-level functions that receive `EngineInternals` first, with
callbacks for instance-only capabilities that still live on `Engine`.

## Files added/changed

- `src/core/engine/operations-router.ts` — operation request translation,
  operation dispatch, operation completion, operation failure, and operation
  execution wrappers.
- `src/core/engine/index.ts` — imports the extracted helpers and keeps thin
  `Engine` shims plus `#createOperationRouterCallbacks`.
- `documentation/engine-split-log/PR-22.md` — records this extraction.

## Functions extracted

Private `Engine` methods moved to module-level functions:

- `#translateOperationRequest`
- `#processOperation`
- `#completeOperation`
- `#failOperation`
- `#runOperationWithResult`
- `#runOperationWithoutResult`

## Notes

- `operations-router.ts` imports `EngineInternals` from `./internals.ts` and
  does not import from `src/core/engine/index.ts`.
- The operation-router complexity suppressions moved with the extracted
  implementations and keep the existing
  `ID:core-engine-translate-operation-request-complexity` and
  `ID:core-engine-process-operation-complexity` identifiers.
- Replay determinism is preserved by keeping the `#processOperation` switch case
  ordering unchanged and routing each case through callbacks without adding
  `Promise.all` or changing await ordering.
- Operation completion and failure still finalize pending timeline entries and
  feed operation results through `Engine` callbacks.
