# PR 21 — Engine schedule extraction

## Scope

Extracts recurring-schedule handling from `src/core/engine/index.ts` into
`src/core/engine/schedules.ts`.

This PR keeps the `Engine` public method surface intact. Public schedule
methods now delegate to module-level functions that receive `EngineInternals`
as their first argument, with callbacks for instance-only capabilities such as
workflow start, workflow state loading, cancellation, and result waiting.

## Files added/changed

- `src/core/engine/schedules.ts` — schedule creation, listing, pause, resume,
  cancellation, cron updates, schedule timer handling, overlap policy handling,
  backfill settling, and scheduled workflow terminal handoff.
- `src/core/engine/index.ts` — imports the extracted helpers and keeps thin
  `Engine` shims.
- `documentation/engine-split-log/PR-21.md` — records this extraction.

## Functions extracted

Public `Engine` methods moved to module-level functions:

- `schedule`
- `listSchedules`
- `pauseSchedule`
- `resumeSchedule`
- `cancelSchedule`
- `updateSchedule`

Private `Engine` methods moved to module-level functions:

- `#refreshScheduledWorkflowState`
- `#startScheduledRun`
- `#applyScheduleOccurrence`
- `#settleBackfillScheduleState`
- `#handleScheduleTimer`
- `#handleScheduledWorkflowTerminal`

## Notes

- `schedules.ts` imports `EngineInternals` from `./internals.ts` and schedule
  storage helpers from `./storage-io.ts`; it does not import from
  `src/core/engine/index.ts`.
- The schedule complexity suppressions moved with the extracted
  implementations and keep the existing
  `ID:core-engine-schedule-complexity`,
  `ID:core-engine-apply-schedule-occurrence-complexity`, and
  `ID:core-engine-handle-schedule-timer-complexity` identifiers.
- Await ordering from the original schedule paths is preserved, including
  schedule state persistence before next-timer writes, fire-and-forget result
  observation before cancellation, inline turn settling during backfill, and
  terminal queue handoff before clearing queued runs.
- `#finalizeScheduledWorkflowTerminal` remains in `Engine` as the error
  handling wrapper around `#handleScheduledWorkflowTerminal`.
