# PR 24 — Engine time/sleep/timer operation extraction

## Scope

Extracts time, sleep, and timer operation handling from
`src/core/engine/index.ts` into `src/core/engine/operations-time.ts`.

This PR follows the existing engine split pattern: extracted helpers run as
module-level functions that receive `EngineInternals` first, with a callbacks
bundle for private `Engine` capabilities that remain on the class.

## Files added/changed

- `src/core/engine/operations-time.ts` — delayed-start timer creation, sleep
  operation processing, sleep resolver registration, delayed workflow start,
  and fired timer dispatch.
- `src/core/engine/index.ts` — imports the extracted helpers, routes sleep
  operations and scheduler timer callbacks through `operations-time.ts`, and
  removes the extracted private `Engine` methods.
- `documentation/engine-split-log/PR-24.md` — records this extraction.

## Functions extracted

Private `Engine` methods moved to module-level functions:

- `#processSleepOperation`
- `#registerSleepResolver`
- `#handleTimerFired`
- `#startDelayedWorkflow`
- `#createDelayedStartTimerEntry`

## Notes

- `operations-time.ts` imports `EngineInternals` from `./internals.ts` and does
  not import from `src/core/engine/index.ts`.
- `TimeOperationCallbacks` carries the remaining instance-private capabilities
  needed by the extracted functions, including workflow state loading, workflow
  failure, serialized state writes, workflow execution start, start headers,
  delayed-start duration parsing, terminal cleanup, schedule timers, and
  workflow timeout.
- The `ID:core-engine-start-delayed-workflow-complexity` and
  `ID:core-engine-handle-timer-fired-complexity` suppressions moved with the
  extracted function implementations.
- Replay determinism is preserved by keeping the original await ordering and
  timer-dispatch branch ordering. No sequential awaits were converted to
  `Promise.all`.
- Dead private `Engine` shims are deleted rather than retained through
  `void this.#method` references.
