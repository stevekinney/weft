# PR 17 — Engine signal extraction

## Scope

Extracts signal delivery, buffered signal scanning, buffered signal
consumption, and generic waiter reverse-index helpers from
`src/core/engine/index.ts` into `src/core/engine/signals.ts`.

This PR keeps the `Engine` public method surface intact. The public `signal`
method and private signal buffer helpers now delegate to module-level
functions that receive `EngineInternals` as their first argument. The
waiter-key helpers are module-level functions because signal, update, and
review waiters all share the same reverse-index shape.

## Files added/changed

- `src/core/engine/signals.ts` — signal delivery orchestration, buffered signal
  lookup and consumption, and generic waiter reverse-index helpers.
- `src/core/engine/index.ts` — imports the extracted helpers, keeps thin
  `Engine` shims where needed, and leaves replay wait orchestration in the
  class.
- `documentation/engine-split-log/PR-17.md` — records this extraction.

## Functions extracted

Public `Engine` methods moved to module-level functions:

- `signal`

Private `Engine` methods moved to module-level functions:

- `hasBufferedSignal`
- `consumeSignal`
- `trackWaiterKey`
- `untrackWaiterKey`

## Notes

- `#processWaitSignalOperation()` remains in `Engine` because it completes
  workflow operations through private Engine machinery.
- `#cleanupWaiters()` remains in `Engine` because it cleans up signal, update,
  review, and sleep waiters together.
- `consumeSignal()` preserves the existing scan-delete-decode sequence without
  adding awaits between scanning a buffered signal key and marking it consumed.
- `signals.ts` does not import types from `index.ts`; it keeps a local
  `TrackedWaiterKeys` structural type to avoid introducing an import cycle.
- No oxlint disable inventory entries moved because the extracted signal
  methods did not contain oxlint disable directives.
