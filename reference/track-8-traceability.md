# Track 8 Traceability Matrix

This matrix is the single source of truth for whether a Track 8 criterion is `closeable` and which wave closes it. It justifies every flip of a `[ ]` to `[x]` in `reference/architecture.md`.

## Schema (fixed)

| field              | meaning                                                                                                                                                   |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`               | matches a slug in `reference/track-8-criteria.md` exactly. Stable: once published, never renamed.                                                         |
| `criterion`        | one-line summary of the criterion (full text lives in `track-8-criteria.md`)                                                                              |
| `category`         | one of `behavioral` \| `cross-cutting-structural` \| `design-invariant` \| `documentation` \| `verification-gate`                                         |
| `status`           | one of `shipped` \| `partial` \| `missing` \| `excluded`                                                                                                  |
| `rationale`        | required when `status = excluded`; optional reviewer-facing context for `shipped` design-invariant rows; empty otherwise                                  |
| `evidence_file`    | one or more comma-separated paths (e.g. `src/server/operation-catalog.ts, src/server/rest-bindings.ts`) or `n/a`                                          |
| `evidence_section` | markdown anchor pinning the closing paragraph (e.g. `runtime-and-deployment.md#track-8-no-second-orchestration-layer-8a-1`) or `n/a`                      |
| `evidence_test`    | named test + file (e.g. `openrpc.test.ts: "JSON-RPC uses named params only"`) or `n/a`                                                                    |
| `evidence_command` | shell command whose successful run closes the row (e.g. `bun test`) or `n/a`                                                                              |
| `evidence_pr_link` | PR URL whose body holds captured command output or whose description cites the row's id, or `n/a`                                                         |
| `wave`             | wave number (`0`–`5`) that closes the row. **Always the wave that flips `closeable` to `true`**, not necessarily the wave the underlying work shipped in. |
| `closeable`        | literal `true` or `false`, computed from the rule below                                                                                                   |

## Coverage rule

Per the Step 0 amendment to `reference/architecture.md`:

> Coverage rule: each behavioral or cross-cutting structural criterion has a real, non-skipped Bun test whose `it(...)` (or `test(...)` — the Bun aliases are equivalent) title contains, as a substring, the exact post-colon sentence of the matching bullet in `reference/track-8-criteria.md`. The bullet's leading slug id and the colon are not part of the quoted span; backticks may be stripped. The title is what `bun test` prints on failure, so this satisfies `final-6`'s "failure message names the criterion" phrasing. Design-invariant criteria are reviewed via the traceability matrix in `reference/track-8-traceability.md` and the rationale paragraphs in `reference/architecture/runtime-and-deployment.md`, not via runtime tests, because no runtime assertion can prove "we did not build a second orchestration layer."

The matrix's `closeable` rule below is the operational form of that amendment. The amendment paragraph in `reference/architecture.md` is the canonical wording; the same paragraph is reproduced here so the matrix is self-contained.

## Closeable definition

A row is `closeable: true` iff one of these branches holds.

**Excluded branch.** `status = excluded` AND `rationale` is a complete-sentence justification AND the wave PR cited in `evidence_pr_link` references the row's `id` in its description.

**Shipped branch.** `status = shipped` AND the category-specific evidence requirement below is satisfied:

- `category = behavioral` or `cross-cutting-structural`: `evidence_test` names a real, non-skipped Bun test whose `it(...)` title quotes the criterion text from `track-8-criteria.md`.
- `category = documentation`: `evidence_file` names a doc file that exists on `main`. If the criterion is closed by a specific section rather than the whole file, `evidence_section` pins the markdown anchor.
- `category = design-invariant`: `evidence_section` is a `path#anchor` pointing at a paragraph in `reference/architecture/runtime-and-deployment.md` (or another committed doc) whose section heading or opening sentence cites the row's `id` verbatim, AND the paragraph contains the rationale.
- `category = verification-gate`: `evidence_command` names the exact command whose successful exit closes the row AND `evidence_pr_link` points at the Wave 5 PR whose description holds the captured terminal output.

`partial` and `missing` are never `closeable: true`; they must flip to `shipped` (or `excluded` with rationale) before the row can close.

## Parity surface inclusion rules

These rules govern which routes belong on the cataloged transport-parity surface and which are intentionally REST-only or anonymous.

- **Cataloged runtime operations** must support REST + JSON-RPC HTTP + JSON-RPC WebSocket + JSON-RPC stdio. The data-driven operations include `weft.schedules.list`, `weft.schedules.get`, `weft.workflows.replay`, and `weft.system.metrics`, alongside the rest of the cataloged surface (verified by `grep -hE "name: 'weft\." src/server/operations/*.ts | sort -u | wc -l`).

  > **Note**: `src/server/operations/` also contains four helper modules — `operation-helpers.ts`, `bulk-filter-helpers.ts`, `sse-stream.ts`, `schedule-faults.ts` — that do not call `defineOperation` and are not counted as operations.

- **Transport-meta endpoints** are REST-only by design: `GET /openapi.json`, `GET /openrpc.json`. They describe the catalog; mounting them as catalog operations creates a circular self-description.
- **Transport-specific endpoints** are REST-only: `GET /v1/workflows/:id/sse`. SSE is HTTP framing; the JSON-RPC analogue is WebSocket subscription notifications.
- **Observability**: `GET /v1/metrics` stays REST-only as `text/plain; version=0.0.4` for Prometheus exposition format. The JSON-shaped form is `weft.system.metrics` on the catalog (different content type, different consumers).
- **Anonymous**: `GET /v1/health` stays REST-only and unauthenticated for liveness probes. No JSON-RPC analogue.

## Naming rule

Cataloged operations follow `weft.<noun>.<verb>` or `weft.<noun>.<sub-noun>.<verb>`. Confirmed by enumeration of the cataloged operations. The five data-driven operation names follow the same shape and do not collide.

## Subscription decision

`grep -l "subscribe" src/server/operations/*.ts` returns no matches as of the Step 0 PR. There is no cataloged subscribe operation today. Subscription parity is covered by existing WebSocket streaming and SSE behavior. This decision is recorded in the **Out-of-scope decisions** section below — _not_ in the criteria id space, because `parity-subscribe-excluded` is not a Track 8 acceptance criterion and its slug must not collide with the stable `8-*` / `final-*` ids.
