# Track 8 Traceability Matrix

This matrix is the single source of truth for whether a Track 8 criterion is `closeable` and which wave closes it. It is the artifact that justifies every flip of a `[ ]` to `[x]` in `reference/architecture.md`.

**Schema** (fixed):

| field              | meaning                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `id`               | matches the slug in `reference/track-8-criteria.md`                                                                      |
| `criterion`        | one-line summary (full text lives in `track-8-criteria.md`)                                                              |
| `category`         | `behavioral` \| `cross-cutting-structural` \| `design-invariant` \| `documentation` \| `verification-gate`               |
| `status`           | `shipped` \| `partial` \| `missing` \| `excluded`                                                                        |
| `rationale`        | required when `status = excluded`; optional reviewer-facing context for `shipped` design-invariant rows; empty otherwise |
| `evidence_file`    | path to the file that closes the row, or `n/a`                                                                           |
| `evidence_test`    | named `it()` + file, or `n/a`                                                                                            |
| `evidence_command` | shell command whose successful run closes the row, or `n/a`                                                              |
| `evidence_pr_link` | PR URL whose body holds captured command output, or `n/a`                                                                |
| `wave`             | wave number (`0`–`5`) that closes the row                                                                                |
| `closeable`        | computed boolean (see rules below)                                                                                       |

**Closeable definition**:

A row is `closeable: true` iff one of the following branches holds.

- **Excluded branch.** `status = excluded` AND `rationale` is a complete-sentence justification AND the wave PR that introduces or finalizes the exclusion cites the row's `id` in its description. Evidence columns may be `n/a`.
- **Shipped branch.** `status = shipped` AND the category-specific evidence requirement below is satisfied.
  - `category = behavioral` or `cross-cutting-structural`: `evidence_test` names a real, non-skipped `it()` whose title quotes the criterion text from `track-8-criteria.md`.
  - `category = documentation`: `evidence_file` names a doc that exists on `main`.
  - `category = design-invariant`: `evidence_file` cites this matrix row plus a documented rationale paragraph in `reference/architecture/runtime-and-deployment.md` (added in Wave 4), AND the architecture.md amendment in the Step 0 PR has accepted that design-invariant criteria are satisfied by document review.
  - `category = verification-gate`: `evidence_command` names the exact command whose successful exit closes the row AND `evidence_pr_link` points at the Wave 5 PR whose description holds the captured terminal output.

`partial` and `missing` are never closeable; they must flip to `shipped` (or `excluded` with rationale) before the row can close.

## Parity surface inclusion rules

These rules govern which routes belong on the cataloged transport-parity surface and which are intentionally REST-only or anonymous. They are referenced by the matrix entries below.

- **Cataloged runtime operations** must support REST + JSON-RPC HTTP + JSON-RPC WebSocket + JSON-RPC stdio. As of Step 0: 39 currently-migrated operations plus the 5 added in Wave 1 (`weft.schedules.list`, `weft.schedules.get`, `weft.tenants.quota.get`, `weft.workflows.replay`, `weft.system.metrics`).
- **Transport-meta endpoints** are REST-only by design: `GET /openapi.json`, `GET /openrpc.json`. They describe the catalog; mounting them as catalog operations creates a circular self-description.
- **Transport-specific endpoints** are REST-only: `GET /v1/workflows/:id/sse`. SSE is HTTP framing; the JSON-RPC analogue is WebSocket subscription notifications.
- **Observability**: `GET /v1/metrics` stays REST-only as `text/plain; version=0.0.4` for Prometheus exposition format. The JSON-shaped form is `weft.system.metrics` on the catalog (different content type, different consumers).
- **Anonymous**: `GET /v1/health` stays REST-only and unauthenticated for liveness probes. No JSON-RPC analogue.

## Naming rule

Cataloged operations follow `weft.<noun>.<verb>` or `weft.<noun>.<sub-noun>.<verb>`. Confirmed by enumeration of the 39 existing operations on `main` (see Step 0 PR description). Wave 1's 5 new names follow the same shape and do not collide.

## Subscription operation decision

`grep -l "subscribe" src/server/operations/*.ts` returns no matches as of the Step 0 PR. There is no cataloged subscribe operation today. Subscription parity is covered by existing WebSocket streaming and SSE behavior. This is recorded as the row `parity-subscribe-excluded` below.
